# バドミントン分析アプリ（ダブルス用）

ダブルスの試合結果を記録し、Eloレーティング・勝率・相性を分析して、次の試合の勝率を予測するWebアプリです。
上級者の多いクラブで練習する中で、「自分の成長を感覚ではなく数値で把握したい」と考えて個人で開発しました。

- 公開URL: https://badminton-app-m6du.onrender.com
- 使用技術: Python / Flask / SQLite / HTML / CSS / JavaScript

## 主な機能

- **試合の記録・削除**（トップページ）: 4人の選手名と、1ゲームのスコア（0〜30点）を入力して記録する。全試合の履歴を一覧で確認でき、削除もできる。同点や、同じ選手名の重複は登録できない。選手名は、表記が完全に一致するものを同一人物として扱う
- **Eloランキング**（トップページ）: 個人Elo・ペアEloの上位5件
- **勝率予測**（`/predict`）: 記録のある4人を指定すると、チーム1の勝率を表示する
- **選手詳細**（`/player/<名前>`）:
  - 勝率、直近5試合の成績
  - Elo、順位、Elo推移のグラフ（Chart.js）、試合数に応じたデータの信頼度（低／中／高）
  - 得失点差の平均・ばらつきと、安定度（安定／普通／波が激しい）
  - 対戦相手ペアごとの勝率と、Eloから期待される勝率との差

初回起動時にDBが空の場合は、架空のサンプルデータが入ります。

## Eloの仕組み

個人Eloは次のように計算します。

1. 初期値は1500
2. チームのEloは、2人の個人Eloの平均
3. 期待勝率は `1 / (1 + 10^((相手 - 自分) / 400))`
4. レートの更新量は `K × (結果 - 期待勝率)`。チーム全体の更新量を、そのチームの2人に同じ量だけ加える
5. `K = 24 × (1 + 2 × 点差割合)`、点差割合は `|スコア1 - スコア2| / (スコア1 + スコア2)`
   （大差の勝ちは、接戦の勝ちより大きく動かす）

勝率予測は、2チームの個人Elo平均だけを使います。
ペアEloは一覧表示用で、**勝率予測には使っていません**（検証で、混ぜると予測が悪化したため。下記）。
なお、ペアEloのK値は当初の設計（試合数別K＋点差/10の加算）のままで、こちらは検証していません。

## 検証

「自分の設計が本当に当たるのか」を確かめるため、`validation/` に検証コードを置いています。

### 方法

- データ: BWF大会の男子ダブルス、約2万試合（2007年〜2026年7月）
  - 出典: GitHubの `SahilMotyar/bwf-match-data` の `md.csv`（BWFの公開結果をもとに整理されたデータセット）
  - 利用条件: 試合結果・大会データの権利はBWFに帰属し、配布元はBWF公式データではないとしている。標準的なOSSライセンスは明記されていない（配布元READMEの記載による。利用前に配布元で確認してください）。そのため、このリポジトリには `md.csv` を含めていません
- 評価指標は、Log Loss・Brier Score・的中率
- **調整期間（2022〜23年）でだけ設定を選び、評価期間（2024年以降）で1回だけ評価する**
- 予測の単位は2通りあり、結果は混ぜない
  - 試合単位: 試合の勝敗を、試合直前のレートで予測する。同日の試合は、全試合を予測してからレートを更新する
  - ゲーム単位（アプリの入力単位）: 次の1ゲームの勝敗を、直前のレートで予測する。同じ試合の2ゲーム目以降は、前のゲーム結果を反映したレートで予測する。別の試合については、同日の他の試合の結果を先に反映させない
- 差の不確かさは、大会単位のブートストラップで95%信頼区間を出す
- 選手名の表記ゆれの統一と、重複の除去を行う

### 分かったこと

1. **ペアEloを70%、個人Eloを30%で混ぜた予測は、個人Eloのみより悪かった**（試合単位の検証。他の混合比は正式には未検証）。
   固定ペアの試合数が少なく、ノイズが大きいためと考えられる（原因は未検証）。
2. **試合単位では、K値を固定して点差を加えると改善した。ただし、アプリの入力単位（1ゲーム）で検証し直すと再現しなかった。**
   1試合で2〜3回レートが動くため、試合単位で決めたKはゲーム単位では大きすぎた。
3. そこで、**ゲーム単位**（1ゲームごとに勝敗を予測してEloを更新）で、K値と点差の効き方を調整期間だけで選び直し、`K=24・点差係数2` を採用した。

### 結果（ゲーム単位、評価期間7,993ゲーム）

| 設定 | 的中率 | Log Loss | Brier |
|---|---|---|---|
| 当初の設計（記録数でK変化＋点差/10を加算） | 67.36% | 0.6052 | 0.2092 |
| 採用した設定（K=24・点差係数2） | 67.86% | 0.6021 | 0.2078 |

- Log Lossの差は −0.0030（95%信頼区間 −0.0056 〜 −0.0006）、Brierの差は −0.0014（同 −0.0024 〜 −0.0004）。ともに0を含まない
- **改善は小さい。** 的中率の差は +0.50pt（同 −0.05 〜 +1.06pt）で、有意とは言えない
- 点差を倍率で反映する効果だけを切り出すと、Log Lossで −0.0023（同 −0.0033 〜 −0.0012）

### 限界

- **国際大会データでの結果であり、クラブ内の試合では未検証。** 少人数で総当たりに近い対戦では、最適なKが違う可能性がある
- **2024年以降のデータは、完全に未使用ではない。** 探索の途中で一部の結果を見ている。設定の選択自体は、調整期間だけで行った
- 調整期間の上位候補は、K=16〜32・係数1〜6で差がほとんどなく、24・2が特別に正しいわけではない
- 大差のとき（例: 21-0）はK=72まで上がる。この挙動は検証していない

### 今後

- クラブの実データが貯まったら、同じ手順（調整と評価を分ける）で再検証する
- 大差時のKに上限を設けるかを検討する
- ペアEloの扱い（表示のみにするか、改良するか）を決める

## 検証コードの実行

`validation/` の中で、`md.csv`（上記の配布元から取得した試合データ）を同じフォルダに置いて実行します。

| ファイル | 内容 |
|---|---|
| `validate_elo.py` | 個人Elo・ペアElo・混合の比較（試合単位） |
| `tune_and_test.py` | 試合単位で、調整期間と評価期間を分けて検証 |
| `tune_and_test_game.py` | ゲーム単位（アプリの入力単位）で、調整期間と評価期間を分けて検証 |

```bash
cd validation
python tune_and_test_game.py
```

試合単位とゲーム単位は、予測するものが違う別のモデルの検証です。結果の数字は混ぜないでください。

## アプリの起動

```bash
pip install flask
python app.py
```

初回起動時に `matches.db` が自動で作られます。デバッグモードは環境変数 `FLASK_DEBUG=1` で有効にします。

## ファイル構成

```
app.py            Flaskアプリの起動
routes.py         ルーティング（記録・予測・選手詳細）
db.py             SQLiteの読み書き
stats.py          Elo・勝率などの集計
utils.py          選手名の正規化
templates/        HTMLテンプレート（base / index / predict / player_detail）
static/           style.css
validation/       Eloの検証コード（md.csv は配布元から取得して置く）
```
